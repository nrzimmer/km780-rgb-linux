FASE 2 -- andamento
-------------------
  DONE    0x01 = select MODE; 0x02 = the mode's complete layout
  DONE    effect catalog: the 8 from the UI, with ID and name (docs/15, docs/16)
  DONE    0x05 = the macro's content: [flag][delay x10ms][HID usage]
  DONE    table at byte 120+ = key assignment, 1 byte per slot
  DONE    function codes: mouse CE-D5, multimedia A5-AB, shortcuts C0-C8
          (C0-C8 contiguous), macro B4, text B8, HID in the low range (docs/17)
  DONE    Disable stores 0x00; Default restores the native HID
  DONE    color per key confirmed on the wire: A=slot21, S=slot30, D=slot34
  DONE    f6 01 XX YY = (column, row) of the physical matrix (docs/18)
  DONE    0x0A = per-page base: 0x00 names, 0x09 macros/texts,
          0x1b/0x1c/0x1d = one base per mode
  DONE    polling rate = byte 8 of the mode (docs/14)

  DONE    gradient: byte 3 = number of stops; a stop = RGB+intensity+position
  DONE    Windows Shortcuts: C0-C8, nine and contiguous. C3=Super+Tab and
          C4=Alt+Tab exist in the firmware and are not in the official UI (docs/17)
  DONE    Timer key = coordinate (04, 07); the OSD is the app's, not the keyboard's
  DONE    read and write are symmetric: the 0x82 returns what the 0x02 wrote,
          byte for byte. The tool's model: read, change one byte, write.
  DONE    0x08 = rasterized gradient: 3 channels x 23 steps, 6 bits (docs/21)
  DONE    a macro's delay has an extended field in the flag's nibble (up to ~41s)
  DONE    a modifier is an ordinary key: Ctrl = HID 0xe0, with no field of its own
  DONE    each effect stores its own duration
  MISSING per-key data of the effects (0x0B, 0x0E, 0x0F, 0x12, 0x15):
          the UI only applies a global effect, so it cannot be exercised through it
  DONE    0x85 = read a macro; a virgin bank replies 0xFF; a re-read right
          after the write returns the old content (docs/09 7b)
  DONE    0x05 only stores with all THREE banks. One or two: an ACK and nothing. The
          third packet closes the write, like the 3rd channel of the 0x09. The
          0x0D frame is not part of it. Measured in mode 3.
  MISSING which macro the 0xB4 runs -- it needs the key pressed to see
  MISSING LED Sleep
  MISSING byte 108 vs byte 119: they are two toggles, which is which is still to be said
  NEVER   Text: the content never goes to the keyboard, only the name.
          A key with the Text function only works with G.SKILL's app running.
NAMING
------------
The "profile" of the 0x01/0x02 is in fact the MODE (M1/M2/M3). The UI's "Profile"
is a PC-side concept and does not exist in the protocol. See docs/16 section 0.

FOOTNOTE: THE OFFICIAL APP CRASHING
------------------------------------
Just for the record, not a task: the official app crashes when enabling effects
in mode 1 (Setting.dll, integer division by zero at 0x1004aa99). No
packet goes out before the crash, so it affects neither the protocol nor our captures.
If anyone ever needs to run the app, the workaround is switching to mode 2.

THE MR/M1/M2/M3 KEYS
-----------------
They switch the mode and record a macro on the keyboard itself, with no software. Windows is
not needed: it can be investigated on Linux by listening to EP 0x83. The consequence
for the tool: the active mode changes underneath the host, so re-read it with
0x81 instead of assuming the last value written.

IMPORTANT WARNING
----------------
Do NOT scan unknown commands on the keyboard. That is exactly what put it
in bootloader: some byte between 0x96 and 0xAF is not a read, despite
having bit 7 set. The convention "bit 7 = read" holds for the confirmed
commands, not for arbitrary bytes.
